## 발견된 버그

### 버그 #1: 미당첨 경품명이 정확히 "미당첨"이 아니면 당첨으로 오처리됨 (심각도: 높음)

- **위치**: `backend/src/domain/entities/Entry.js` 53~54행 `statusForDrawnPrize()`
- **현상**: 미당첨 처리 기준이 `prize.name === '미당첨'` 하드코딩 문자열 완전일치다. 관리자가 도메인 정의서(`docs/1-domain-definition.md` 96행)의 "꽝인 경우 '미당첨'으로 등록" 규칙을 모르고 "꽝", "탈락", "다음 기회에" 등 다른 이름으로 미당첨 항목을 등록하면, 해당 항목에 당첨된 참여자에게 **"축하합니다! 'OO' 당첨"이 표시되고 DB에도 `status=WON`으로 저장**된다.
- **재현 과정**: 룰렛 이벤트에 경품 "상품권"(weight 1) / "커피쿠폰"(weight 5) / **"꽝"**(weight 94)을 등록 → 비회원 참여 → "꽝"에 당첨되자 "축하합니다! '꽝' 당첨" 표시 (`s1-04-roulette-result-BUG-lost-shown-as-won.png`). DB 조회 결과도 `status: WON`으로 확인.
- **근본 원인**: 이 판정 로직이 유일한 방어선이며, **관리자 등록 화면(`AdminEventFormPage`)에 "미당첨 항목은 정확히 '미당첨'으로 입력하세요" 같은 안내가 전혀 없다.** 즉 관리자가 실수하기 매우 쉬운 함정이 있는데 아무 가드도 없다.
- **재검증**: 경품명을 "미당첨"으로 정정한 뒤 동일 조건 재현 시 "아쉽게도 미당첨입니다"로 정상 표시됨 (`s1-04-roulette-result-lost-correct.png`).
- **권장 조치**: (a) 경품 등록 폼에 미당첨 규칙 안내 문구 추가, 또는 (b) 이름 매칭 대신 명시적 `isLosing` 플래그를 스키마에 두는 구조 변경. 단 (b)는 스키마 변경이 필요하므로 우선 (a)부터 권장.

### 버그 #2: 마감일 경과로 lazy 종료된 이벤트는 마감일시를 연장해 재개할 수 없음 (심각도: 중간)

- **위치**: `backend/src/application/usecases/events/UpdateEventUseCase.js` 18~22행
- **현상**: 이벤트 수정 API가 `existing.effectiveStatus(now)`(현재 시각 기준 계산된 상태)만으로 종료 여부를 판단해, `종료` 버튼으로 **명시 종료된 적이 없고** DB의 실제 `status` 컬럼은 여전히 `SCHEDULED`/`ONGOING`인데 `endAt`이 지나 계산상 `종료`로 보이는 이벤트도 무조건 "종료된 이벤트는 수정할 수 없습니다"로 거부한다.
- **문서 근거**: `docs/4-user-scenario.md` S-10 대안 흐름: *"관리자가 마감일시를 연장한 경우: 다음 조회부터 즉시 다시 진행중으로 계산된다(별도 재개 처리 불필요). **단** 관리자가 '종료' 버튼으로 명시 종료한 이벤트는 endAt과 무관하게 종료 상태를 유지한다."* — 즉 명시 종료와 마감 경과(lazy)를 구분해서 후자는 연장으로 재개 가능해야 한다.
- **재현 과정**: `startAt=2026-08-10, endAt=2026-08-20`으로 이벤트 생성(오늘 2026-08-21) → DB의 `status` 컬럼은 `SCHEDULED`(참여신청 0건이라 자연히 ONGOING을 거치지도 않음)인데도 목록에는 계산상 `종료`로 표시됨 → 관리자 수정 화면에서 `마감 일시`를 미래로 연장 후 저장 → **"종료된 이벤트는 수정할 수 없습니다" 토스트로 거부됨** (`s10-04-BUG-lazy-closed-cannot-extend.png`).
- **영향**: 관리자가 마감일을 실수로 짧게 등록했거나 이벤트를 연장하고 싶을 때, 이미 endAt이 지나버린 경우 구제할 방법이 전혀 없다(새 이벤트를 다시 만드는 것 외에는 불가). 도메인 문서가 명시적으로 허용한 운영 시나리오가 실제로 막혀 있다.
- **권장 조치**: `UpdateEventUseCase`에서 "종료" 판정 시 `existing.status === EVENT_STATUS.CLOSED`(DB에 저장된 명시 종료 여부)만 검사하도록 수정하고, `effectiveStatus`가 계산상 CLOSED이지만 저장값은 아직 CLOSED가 아닌 경우는 "진행중 이벤트"에 준하는 필드 잠금 규칙(대상유형/참여방식/시작일시 불가, 마감일시는 연장만)을 적용.

## 시나리오별 상세 결과

### S-1. 비회원 룰렛 참여 골든패스

2. 이벤트 상세에서 비회원 입력 폼 + 보유기간 고지 문구 정상 노출 (`s1-02-event-detail-guest-form.png`)
3. 정보 입력 + 동의 체크 후 활성화된 참여 버튼 확인 (`s1-03-guest-form-filled-consent-checked.png`)
4. 참여 → 룰렛 애니메이션 후 결과 확정. 미당첨(`s1-04-roulette-result-lost-correct.png`) / 당첨(`s1-05-roulette-result-won.png`) 케이스 모두 확인. 100회 추첨 샘플링 결과 당첨 4/100(설정 확률 6%와 유사한 범위)로 추첨 알고리즘(`drawPrize.js`) 자체는 정상.
5. **버그 #1 발견** (위 참조)

### S-2. 미동의 참여 거부
- 정보를 입력했지만 동의 미체크 시 "참여하기" 버튼이 `disabled` 상태로 유지됨 (`s2-01-consent-unchecked-button-disabled.png`)
- 클라이언트 검증을 우회해 `consent:false`로 직접 API 호출 시 서버가 `400 CONSENT_REQUIRED`로 거부, 레코드 미생성 확인

### S-3. 회원 전용 이벤트에 비회원 접근
- 비회원으로 회원 전용 이벤트 상세 접근 시 입력 폼 대신 "회원 전용입니다. 로그인 후 참여해 주세요" + 로그인/회원가입 버튼 노출 (`s3-01-member-only-guest-blocked.png`)
- 인증 없이 참여 API 직접 호출 시 `403 TARGET_TYPE_MISMATCH` 확인

### S-4. 중복 참여 거부
- 이미 참여(당첨 확정)한 이메일로 재참여 시도 → 신규 추첨 없이 "이미 참여하셨습니다" 토스트, 룰렛 미동작 확인 (`s4-01-duplicate-entry-toast.png`)

### S-5. 재추첨 시도 거부
- 결과 화면에 "다시 돌리기" 등 재시도 UI가 존재하지 않음, 캡처 안내와 목록 링크만 존재 확인 (`s5-01-result-no-retry-button.png`, S-1 당첨 화면과 동일 캡처)
- 새로고침 후 동일 이메일로 재참여 시도 시 S-4와 동일하게 `DUPLICATE_ENTRY`로 거부되어 재추첨이 일어나지 않음을 확인

### S-6. 신규 회원가입 → 로그인 → 회원 전용 참여
1. 회원가입 폼 정상 입력 (`s6-01-signup-form.png`) → 가입 성공 후 로그인 화면으로 이동
2. 동일 이메일 재가입 시도 → "이미 가입된 이메일입니다" (`s6-02-signup-duplicate-email.png`)
3. 오답 비밀번호 로그인 시도 → "이메일 또는 비밀번호가 일치하지 않습니다" (`s6-03-login-wrong-password.png`)
4. 정상 로그인 후 회원 전용 이벤트 상세: 개인정보 입력 폼 없이 동의 체크박스만 노출 (`s6-04-member-participation-no-input-form.png`)
5. 참여 완료 → "참여가 완료되었습니다" (`s6-05-simple-participation-complete.png`)

### S-7. 룰렛 참여신청 취소 불가 확인
- 회원이 룰렛(미당첨)·단순참여 2건을 보유한 상태에서 마이페이지 진입 시 룰렛 건에는 취소 버튼이 없고, 단순참여 건에만 취소 버튼 노출 (`s7-01-mypage-entries-roulette-no-cancel.png`)
- 룰렛 건 취소를 서버 API로 직접 시도 시 `400 VALIDATION_ERROR "룰렛 게임형 참여신청은 취소할 수 없습니다."`로 거부 확인 (서버가 최종 방어선임을 검증)
- 단순참여 건 취소 → 상태가 "취소"로 전환 (`s7-02-mypage-after-cancel.png`) → 동일 이벤트 재참여 → 새 레코드 생성 없이 기존 레코드가 "신청완료"로 복귀 (`s7-03-mypage-after-reapply.png`, DB에서 동일 entry id로 상태만 변경됨을 확인)

### S-8. 이벤트 등록·운영·조기종료 (관리자)
1. 시드 관리자 계정 로그인 (`s8-01-admin-login-and-event-list-empty.png`)
2. 룰렛 이벤트 등록 폼: 대상유형/참여방식/일정/상단노출/경품(3건, weight 1·5·94) 입력 (`s8-02-admin-event-form-roulette-prizes.png`)
3. 총 4개 이벤트(룰렛/회원전용 단순/공통 단순/마감된 이벤트) 등록 후 목록에서 상태·참여자수·상단노출 정상 표시 확인 (`s8-03-admin-event-list-4events.png`)
4. "종료" 버튼 클릭 시 확인 다이얼로그 노출("종료 후에는 되돌릴 수 없고, 신규 참여신청을 받지 않습니다") (`s8-04-early-close-confirm-dialog.png`) → 확정 시 즉시 "종료" 상태로 전환
5. 진행중 이벤트 수정 화면에서 대상유형/참여방식/시작일시가 비활성화(회색)로 잠기는 것을 확인 (`s8-05-edit-ongoing-event-locked-fields.png`)
6. 경품 0건인 채로 룰렛 이벤트 저장 시도 → "룰렛 게임형은 경품이 1건 이상 필요합니다" 저지 (`s8-06-roulette-no-prize-error.png`)
7. 경품 weight를 0으로 저장 시도 → "weight는 1 이상의 정수여야 합니다" 인라인 검증 (`s8-07-weight-validation-error.png`)
8. **버그 #2 발견** (위 참조) — S-8 자체의 골든패스/예외 흐름 완료조건은 모두 통과했으나, 연관된 후속 시나리오(S-10)에서 이 문제가 노출됨

### S-9. 종료 후 신규 참여 없음 확인 (관리자)
1. 종료 처리 직후 이벤트 목록에서 참여자수 158건 확인 (`s9-01-admin-event-list-closed-158entries.png`)
2. 참여신청 목록에서 158건 전체를 신청 시각순으로 표시, 회원/비회원 구분·업체명·이메일·동의시각·경품·상태 컬럼 모두 정상 (`s9-02-admin-entries-list-158.png`)
3. 참여자 화면에서 동일 이벤트 상세를 열면 "종료된 이벤트입니다" 안내로 참여 영역 대체 확인 (`s9-03-participant-closed-event-detail.png`)
4. 종료 후 참여 API 강제 호출 시 `409 EVENT_CLOSED` 거부, DB 카운트 158건 그대로 유지 확인
5. 참여신청 0건인 이벤트의 목록 화면에서 "참여신청이 없습니다" 빈 상태 문구 확인 (`s9-04-empty-entries-list.png`)

### S-10. 마감일자 경과로 자동 종료된 이벤트
