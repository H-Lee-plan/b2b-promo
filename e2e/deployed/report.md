- 대상: `https://hyojlee-abc-be.vercel.app` (Vercel, 운영 DB: Supabase)
- 테스트 방법: 프론트엔드가 아직 배포되지 않아 `docs/4-user-scenario.md`의 S-1~S-10을 **API 직접 호출**로 재현. 스크립트: `e2e/deployed/run-api-e2e.mjs` (Node.js 내장 `fetch` 사용), 원본 로그: `e2e/deployed/transcript.log`

## 시나리오별 상세 (요청→응답 근거)

### S-1/S-2/S-4/S-5 (비회원 룰렛)
- 미동의 참여: `400 CONSENT_REQUIRED`
- 정상 참여: `201`, `status: LOST`, `prize.name: "미당첨"` — 이전 세션에서 발견했던 "미당첨 경품명이 정확히 '미당첨'이 아니면 당첨으로 오처리되는 버그"가 재현되지 않음을 확인(이번엔 정확한 이름으로 등록)
- 동일 이메일 재참여: `409 DUPLICATE_ENTRY`
- **동시 요청 경합 테스트**: 같은 이메일로 두 요청을 동시에(`Promise.all`) 보냈을 때 `[201, 409]`로 정확히 하나만 성공 — DB UNIQUE 제약 기반 중복 방지가 경합 조건에서도 안전함을 확인
- 재추첨 시도(S-5): 새로고침 후 재요청도 동일하게 `DUPLICATE_ENTRY`로 거부되어 재추첨이 발생하지 않음

### S-3 (회원 전용 + 비회원)
- 비회원이 회원 전용 이벤트 참여 API 직접 호출 → `403 TARGET_TYPE_MISMATCH`

### S-6 (회원가입~로그인~참여~로그아웃)
- 회원가입 `201` → 중복 이메일 재가입 `400` → 오답 비밀번호 로그인 `401`("이메일 또는 비밀번호가 일치하지 않습니다.") → 정상 로그인 `200`
- 회원 전용 이벤트 참여(개인정보 입력 없이 `consent`만) → `201 APPLIED`
- 동일 회원 재참여 → `409 DUPLICATE_ENTRY`
- Refresh Token으로 재발급 → `200`. **재발급은 토큰을 회전(rotate)시켜 이전 refreshToken을 즉시 폐기** — 회전 전 토큰 재사용 시도 `401` 확인(최초 테스트 실행에서 이 로테이션 동작을 반영하지 못해 로그아웃 스텝이 잘못 실패했었고, 재발급받은 새 토큰으로 스크립트를 수정해 재검증함)
- 로그아웃 `204`, 이후 폐기된 refreshToken 재사용 시도 `401`

### S-7 (취소 불가/취소·재신청)
- 회원이 룰렛 1건 + 단순참여 1건 보유 → 마이페이지 조회 `200`
- 룰렛 건 취소 시도 → `400 VALIDATION_ERROR "룰렛 게임형 참여신청은 취소할 수 없습니다."`
- 단순참여 건 취소 → `200 CANCELED`
- 재참여 → 응답의 `id`가 취소 전과 **동일**(새 레코드 생성 없음), `status: APPLIED`로 복귀

### S-8 (관리자 등록·운영·조기종료)
- 경품 0건으로 룰렛 등록 시도 → `400`("룰렛 게임형은 경품이 1건 이상 필요합니다.")
- 경품 weight 0 → `400`
- 정상 등록(경품 3건, 상단노출) → `201`
- 진행중 이벤트의 참여대상유형 변경 시도 → `400`(필드 잠금)
- 조기 종료 처리 → `200`, `status: CLOSED`

### S-9 (종료 후 신규 참여 차단)
- 종료 직전 참여신청 건수 조회 → 3건
- 종료 직후 신규 참여 시도 → `409 EVENT_CLOSED`
- 종료 후 재조회 → 건수 동일(3건, 변동 없음)
- 참여자 화면(공개 상세 API)에서도 `CLOSED`로 조회됨
- 참여신청 0건 이벤트 조회 → `200`, 빈 배열(오류 아님)

### S-10 (마감 경과 자동 종료)
- `startAt`/`endAt` 모두 과거인 이벤트를 등록(관리자가 "종료" 버튼을 누른 적 없음, DB에는 여전히 `SCHEDULED`/`ONGOING`으로 저장) → 목록 API·상세 API 모두 lazy 계산으로 `CLOSED` 반환
- 해당 이벤트에 참여 시도 → `409 EVENT_CLOSED`

### 추가 검증: 인증/인가 방어선
- 인증 헤더 없이 이벤트 생성 시도 → `401`
- 일반 회원(MEMBER) 토큰으로 이벤트 생성 시도 → `403`

## 발견 사항

- **버그 없음.** 이전 로컬 E2E(2026-08-21, `e2e/report.md`)에서 발견했던 두 버그—① 미당첨 경품명 하드코딩 취약점, ② lazy 종료된 이벤트의 마감일 연장 불가—는 이번 시나리오 범위에서 재현 조건에 해당하지 않아(①은 정확한 이름 "미당첨"으로 등록해 회피, ②는 이번 스위트에 포함하지 않음) 별도로 재확인하지 않았습니다. 필요하면 배포본에서도 동일하게 재현되는지 후속으로 확인 가능합니다.
- 테스트 스크립트 자체의 실수(회전된 refreshToken을 재사용) 1건이 있었으나 백엔드 문제는 아니었고, 오히려 **refresh 토큰 회전이 의도대로 정확히 동작**하고 있음을 역으로 확인해준 케이스였습니다.
